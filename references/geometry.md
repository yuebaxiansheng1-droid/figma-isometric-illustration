# 曲面与挤出几何

轮廓必须按形状与空间关系主动绘制，不从位图分割、追踪或转曲生成；本页的解析、投影和挤出仅处理已经绘制的几何路径。

仅在需要构建或修复圆角、凹形图标、内弧及连续侧面时读取。使用 [bezier-extrusion.js](../scripts/bezier-extrusion.js) 保留真实曲线，不为普通直线几何增加复杂流程。

## 投影与轮廓

先在物体平面创建轮廓，再变换所有贝塞尔端点和控制点。平面投影为仿射变换，因此原有曲线准确保留：

`[x,y] = O + u·A + v·B`

按参考图选择 A、B，不把示例角度固定为设计约束。高度方向或物体法向在屏幕上的投影记为 D，厚度取 t，则挤出偏移为 `t·D`。

区分外轮廓、孔洞、凹槽和不连通物体。先确认简单轮廓的方向；方向错误会遗漏箭头和工具的可见厚度。

## 连续侧面

脚本把 L、Q 转为精确的 C 表达，保留原有 C。曲线不会采样成几何线段。

对于屏幕 y 向下、顺时针外轮廓，沿轮廓切向 T 的可见挤出侧面满足 `cross(T,D)<0`。脚本统一轮廓方向，在 `cross(B'(t),D)=0` 的位置用 de Casteljau 分割曲线，按连续可见链构建闭合侧面：

1. 沿顶面可见链前进。
2. 连接到偏移后的末端。
3. 按相反方向返回对应底部曲线；反向 C 的控制点同时交换。
4. 闭合到起点。

每个连续链是一条闭合轮廓；一个物体的可见侧面可放在同一个 Vector 中，必要时包含多个不连通轮廓。不要连接被遮挡链之间的空白。通过渐变连续表现弧面明暗；真实不同平面的面色按场景决定。

脚本的少量采样仅用于判断轮廓方向，不生成分段顶面或分段侧面。

## 脚本使用

输入限制：
- 一条简单闭合轮廓，明确写出每个 M/L/Q/C/Z 命令，使用大写与十进制坐标。
- 不支持复合路径、SVG A 弧命令、自相交或孔洞拓扑；不要把这些输入作为普通外轮廓传入。
- 孔洞需要独立处理内轮廓、内壁和遮挡。可以使用原生布尔运算或准确的对应曲线。
- 挤出向量要来自本物体平面与法向，不由脚本自动判断物体类型。
- 数值输出约保留四位小数，避免坐标量级过大。

Node 环境：
```js
const G = require('./scripts/bezier-extrusion.js');
const contour = G.roundPolygon([[110,18],[202,70],[110,122],[18,70]],12);
const top = G.topPath(contour);
const side = G.sidePath(contour,[0,16]);
```

Figma 环境：先读取脚本内容，将其完整嵌入 use_figma 的 code 中，然后调用 `IsoBezier`。该脚本是纯 JavaScript，不在 Figma 中读文件或 require 模块。按 figma-use 技能创建原生 Vector 或导入含上述路径的 SVG，分别命名顶面和连续侧面，并返回所有新建/修改的节点 ID。

## 圆柱、圆按钮与插头

圆形面在物体局部平面画成连续三次贝塞尔圆，端点与控制点一同投影。底部对应曲线只沿本物体法向平移，长短轴和切线关系保持一致。用 `sidePath(contour, offset)` 求可见弧的切点并闭合侧壁，顶面最后覆盖隐藏区域；底圆不是侧壁。

放大检查两端连接线是否沿同一挤出方向，上下弧是否对应、切线是否平滑、侧壁是否漏缝。共享边界只描一次。圆形按钮阵列沿承载面排列；接口的孔口继承所在面，插头的圆截面垂直于自身轴向，两者不能都画成未投影的屏幕正圆。

## 按钮的按下状态

从同组按钮的基础几何推导状态，不重新设计一枚无关的按钮。键面、图标、圆角、描边和材质沿用同一造型规则，保留其投影、横向尺寸和排列锚点。

- 确定实际运动轴；通常沿按钮所在平面的法向。键面端点、贝塞尔控制点和依附图标一起平移，不能只移动图标或通过屏幕纵向缩放制造下沉。
- 键帽实际厚度按实体结构保留。运动后由外壳或凹槽遮住更多侧壁；重新求可见边界与连续闭合侧壁，处理洞口内壁、遮挡和接触阴影。侧壁完全被遮住时不强行露出厚度，也不用两枚相同色块错位叠放。
- 验收默认与按下状态的平行边、圆角和共享边界，确认下沉深度有清楚的空间依据；材质或颜色变化只在参考图或用户明确要求时采用。

## 标签与洞的特殊处理

标签先在本地平面构建完整圆角气泡及指示角，再投影，使用本平面法向挤出。正面、上边及窄侧面的转角共享曲线，不能手绘一个不对应的厚度轮廓补在后面。

洞是负空间：洞口属于承载面，内壁朝内部，内部被洞口限制。确定内壁可见方向与外侧面相反；必要时使用遮罩或布尔几何确保内壁不超出洞口。根据底座高度处理遮挡，不用额外的凸起底板冒充洞。

## 复杂实体与共享边界

车辆等复杂实体的整体外形需要单独设计；闭合路径本身不能保证造型合理。用少量有明确切线关系的曲线构建连续轮廓，将轮拱、凹口和体积转折纳入对应外缘。不同物体或真实不同的面仍可分别绘制，不能为了减少节点数强行合并。

布尔运算可用于合适的洞口或简单组合，但复杂曲面合并后可能留下内部回路、尖刺或极短路径。放大检查结果；若同一接缝反复补线仍有缺陷，直接重建该部分的连续轮廓，不继续堆叠补片。共用边界只保留一次描边；玻璃等依附面可以填充而不描整圈边。

## Figma 导入与局部更新

修改 vectorPaths、尺寸或嵌套变换后，重新核对矢量、遮罩与依附细节的实际位置。分组包围框可能重算，不能只复用修改前的局部坐标；用当前父级坐标和绝对变换确认对齐，再检查实际渲染。遇到异常按当前 figma-use 的恢复约定处理，不根据旧节点状态盲目重试。

复用颜色变量时，绑定 paint 的回退颜色应与变量当前值一致，不能用临时中灰作为占位。分别核对主组件与场景实例的实际颜色，避免覆盖属性或导入差异掩盖问题。具体 API 与 paint 格式仍以当前 figma-use 为准。

## 针对性检查

- 放大查看圆角和内弧：轮廓曲线连续，侧面只有必要的闭合轮廓，无大量拼接小面。
- 检查箭头尖端、扳手开口和孔洞：外缘、内侧与底部对应准确。
- 反向轮廓也应得到同样的可见厚度。
- 整体渲染检查面与面之间的衔接、遮挡、颜色和接触关系。几何函数验证通过不能代替视觉验收。
