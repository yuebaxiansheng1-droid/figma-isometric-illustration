# 车辆与建筑细节

在场景包含车辆、建筑门洞、玻璃立面或室内家具，或这些物体的造型与比例需要重做时读取。共同投影与连续侧面按 [曲面与挤出几何](geometry.md)；参考匹配与首版质量按 [参考图还原与精修](reference-fidelity.md)。

## 车辆：先形成完整、合理的造型

先确定车型、朝向和车身长宽高，再定位前后轮轴、引擎盖、风挡、车顶和尾部。参考还原时保留参考车型特征；用户允许原创或要求重新构思时，可以重建完整车型，避免继续沿用已失衡的旧外形。

用一条有明确体积转折的连续外轮廓统领车身，轮拱纳入外缘。必要的车身表面和材质可分开填充，但不能靠互不连续的色块拼出主造型。先检查车头、车顶和车身整体关系，再画灯、门缝、把手等细节。

轮胎与轮毂在车轮所属平面绘制圆形后统一投影；轮拱圆弧与可见车身对应。检查两轮尺寸、轮距、落地高度、车头与尾部悬伸，不以车窗或车顶遮挡轮廓错误。曲线转接保持合理切线，避免尖刺、短折线和反复补片。

## 车顶与玻璃的联动

车顶在车身的局部水平面中构建，再用共同投影处理端点和控制点。除车型本身的曲面变化外，平行直边继承该面方向；不在屏幕坐标中单独旋转或非等比拉伸车顶。

车顶偏宽、偏方或圆角过大时，先调整局部长宽、前后锚点与圆角，而不是先增加饰线。修改应同步涉及：

- 外轮廓中车顶到前后车身的连接段；
- 风挡、侧窗上沿和相关柱线；
- 车顶共享边界、填充与车身遮罩。

车顶与车窗上沿共用的边只描一次。玻璃优先用填充区分材质，必要的窗框和柱线分别表达，避免屋顶描边与玻璃描边形成双线。检查前后窗框是否过宽、圆角附近是否出现额外线段，以及车顶是否像悬浮盖板。

[isometric-vehicles.js](../scripts/isometric-vehicles.js) 提供经过当前项目验证的四个车型底稿，可用于标准 ±30° 轴测且用户允许这些造型的任务。它是可修改示例，不是所有车辆任务的默认样式；近似轴测、其他车型或大幅改变车身尺寸时，需要按参考调整投影、锚点与比例。

该案例的车顶长宽比约为 1.41–1.52，圆角从 4 调为 2.4 后更协调；这是案例参数，不是通用车辆规范。是否收窄或拉长仍以车型与实际渲染为准。

## 门洞：用向内的空间表达深度

分清门洞开口、内壁、门框、门扇、门槛与雨棚。内壁在洞口以内形成可见厚度，内部暗面与接触阴影表达凹入。门扇位置与门框深度一致；卷帘纹理服从门扇平面。

雨棚是独立的向外实体，具有顶面和厚度，不能用它代替门洞深度。检查内壁与门扇的前后遮挡，避免门洞像贴在墙上的纯色矩形。建筑外壳仍应保留连续曲面。

## 玻璃与室内家具：同时处理材质和尺度

玻璃立面拆分为透明面、窗框或立柱、克制的反射和接触阴影；室内物体单独绘制，并置于正确前后关系中。不要用不透明纯色块遮掉室内结构，也不要把室内车辆的颜色直接当作玻璃面色。

柜台先确定柜体、桌面、支架和显示器的实体关系。桌面有薄厚度，显示器有屏幕、外壳、支架与底座；它们分别遵守自己的承载面方向，不共用一个随意的屏幕旋转角。

用同场景车辆、门高或其他可靠对象校准尺度。当前案例中柜台长度约为车辆长度的一半，使其明显小于车辆；其他场景依据实际使用关系确定，不能固定照搬 30 × 15 × 12 或直接比较屏幕包围框宽度。

## 道路、logo 与标牌

道路轮廓、平台边界和停车线先在地面平面中布局，再统一投影。转角用连续曲线；虚线方向与道路、停车位关系一致，不靠局部屏幕旋转修正方向。

logo 和工具图案先按含义构造完整轮廓，再投影到所在标牌平面。小尺寸仍需清楚辨认、平滑转角和合理留边。截图自动描摹生成可编辑节点，不等于获得平滑、正确的图案；需要去除多余节点、短线、重叠边和错误开口，必要时重新绘制。

## 底稿调用与检查

Node 中调用已有曲面辅助函数；在 Figma 中先嵌入 bezier-extrusion.js，再嵌入车型脚本。脚本只返回 SVG 和几何信息，不创建或修改 Figma 节点：

```js
const makeVehicles = require('./scripts/isometric-vehicles.js');
const cars = makeVehicles();
const body = cars.A.body;     // 单一闭合车身轮廓
const detail = cars.A.detail; // 玻璃、共享车顶边界及必要细节
const complete = cars.A.svg;  // 可编辑 SVG，含对应车身裁切
```

修改示例参数可通过 `makeVehicles({vehicles:{A:{roofInset:4.6,roofRadius:2.2}}})`。默认车身比例与窗体锚点已匹配；大幅改变 L、W、H、roofBack 或 roofFront 时需联动其他尺寸并重新检查，不能仅凭脚本运行成功判断造型正确。

在主组件中通过完整外形、相对尺度、曲线衔接和实际颜色检查，再复用到场景；确认实例位置、尺寸、朝向与覆盖属性符合要求。局部更新后按 geometry.md 核对遮罩和依附细节，交付同时检查场景整体与车辆、门洞或玻璃的放大图。
